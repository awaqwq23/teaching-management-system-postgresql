## 4. 并发与事务结论

并发用例使用两个独立 `Connection`，在同一 `CountDownLatch` 放行后同时向班 1 插入选课；该班容量先改为 3、已有 2 人。触发器先对教学班行执行带 `enrolled_count < capacity` 条件的原子更新，后插入选课记录。结果是一个事务成功、另一个收到 `23514`，最终 `enrolled_count` 和真实选课数都为 3。

批量选课按教学班 ID 升序执行，减少反向加锁导致的死锁概率；任一插入失败即 `rollback`，人数触发器的变化随事务一起撤销。应用不把“`UPDATE` 已执行”当作已提交，也不在提交失败时重试或吞掉异常。
