# 高校教学管理系统逻辑设计与规范化

## 1. 关系模式与数据字典

关系模式采用英文复数表名。前五表的 ID 均为 `bigint` identity 主键，选课表使用两个外键组成的联合主键。除 `students.email` 和 `enrollments.grade` 外，以下所有属性均为 `NOT NULL`。字符串要求去除两端普通空格后非空；可空邮箱在非空时也须满足该要求。

| 关系 | 属性与数据类型 | 主键与备用候选键 |
|---|---|---|
| `departments` | `department_id bigint identity`；`department_code varchar(12)`；`department_name varchar(80)` | PK：`department_id`；UK：`department_code`、`department_name` |
| `students` | `student_id bigint identity`；`student_no varchar(20)`；`student_name varchar(60)`；`department_id bigint`；`email varchar(120)` 可空；`admission_year smallint` | PK：`student_id`；UK：`student_no`；另有可空 `email UNIQUE` |
| `teachers` | `teacher_id bigint identity`；`teacher_no varchar(20)`；`teacher_name varchar(60)`；`department_id bigint` | PK：`teacher_id`；UK：`teacher_no` |
| `courses` | `course_id bigint identity`；`course_code varchar(20)`；`course_name varchar(100)`；`credits numeric(3,1)`；`department_id bigint` | PK：`course_id`；UK：`course_code` |
| `teaching_classes` | `class_id bigint identity`；`class_code varchar(24)`；`course_id bigint`；`teacher_id bigint`；`semester varchar(11)`；`capacity integer`；`enrolled_count integer DEFAULT 0` | PK：`class_id`；UK：`class_code` |
| `enrollments` | `student_id bigint`；`class_id bigint`；`enrolled_at timestamptz DEFAULT CURRENT_TIMESTAMP`；`grade numeric(5,2)` 可空 | PK：`(student_id, class_id)`；无额外备用候选键 |

### 1.1 外键

| 子表外键 | 被引用主键 |
|---|---|
| `students.department_id` | `departments.department_id` |
| `teachers.department_id` | `departments.department_id` |
| `courses.department_id` | `departments.department_id` |
| `teaching_classes.course_id` | `courses.course_id` |
| `teaching_classes.teacher_id` | `teachers.teacher_id` |
| `enrollments.student_id` | `students.student_id` |
| `enrollments.class_id` | `teaching_classes.class_id` |

七条外键均采用 `ON DELETE RESTRICT`，不设置级联删除。现有 `sql/create_tables.sql` 未显式声明 `ON UPDATE`，因此更新采用默认 `NO ACTION`；这些外键没有声明延迟检查，不允许更新造成悬空引用。不能将其字面定义写成已显式设置 `ON UPDATE RESTRICT`。普通外键字段修改为另一个存在的父键通常是允许的，但选课的两个身份字段另由更新检查触发器禁止修改。

### 1.2 值域约束

| 属性 | 值域或规则 |
|---|---|
| `admission_year` | 2000 至 2100，含端点 |
| `credits` | 大于 0 且小于等于 10，存储一位小数 |
| `semester` | `YYYY-YYYY-[12]`，两个学年均为四位数字，后一年等于前一年加一 |
| `capacity` | 1 至 500，含端点 |
| `enrolled_count` | 0 至本行 `capacity`，含端点；另外须等于实际选课数 |
| `grade` | `NULL` 或 0 至 100，存储两位小数 |
| `email` | 可空；非空值唯一且去除两端普通空格后非空 |

## 2. 函数依赖的语义与判断口径

对关系 R，函数依赖 `X → Y` 表示任意两个合法元组在 X 上相等时，在 Y 上也相等。候选键 K 满足 `K⁺ = R`，且 K 的任一真子集均不能决定 R 的全部属性。

以下给出能生成本项目业务函数依赖的依赖组；右侧列出多个属性时，可逐项拆成右侧单属性形式。不把外键本身误认为函数依赖：外键首先是包含依赖，不能推出“院系 ID 决定该院系的所有学生”。

传统范式推导采用关系模型的原子值与依赖语义。SQL 允许邮箱、成绩为 `NULL`，它们在实现上分别表示未知邮箱、未录成绩；此处不把可空唯一列提升为候选键，也不使用 `NULL = NULL` 推导任何新的业务依赖。

## 3. 逐表函数依赖与 1NF、2NF、3NF 推导

### 3.1 院系 departments

```text
department_id → department_code, department_name
department_code → department_id
department_name → department_id
```

由第一条及传递规则，`{department_id}`、`{department_code}`、`{department_name}` 的闭包均覆盖全表；各自为单属性，均不可再约简，所以三者都是候选键。全表三个属性均为主属性。

- **1NF：** 每行一个院系，代码与名称为单值字符串，没有“院系列表”或重复列组。
- **2NF：** 每个候选键只有一个属性，不存在非主属性对复合候选键真子集的依赖。
- **3NF：** 已识别的非平凡依赖左部均为候选键或其超集，满足“左部为超键或右部为主属性”的判据。在该依赖集合下也满足 BCNF。

若把院系名复制到每个学生、教师、课程行中，会出现一次更名需要多处更新的问题；独立院系表把更名集中到一行。

### 3.2 学生 students

```text
student_id → student_no, student_name, department_id, email, admission_year
student_no → student_id
```

`student_id⁺` 覆盖全表；由 `student_no → student_id` 及第一条，`student_no⁺` 也覆盖全表。候选键为 `{student_id}`、`{student_no}`，主属性为这两个属性。邮箱允许多个空值，不是候选键；不根据样本推断姓名或入学年份唯一。

- **1NF：** 每行只保存一个学生的一份基本资料，邮箱为至多一个值，没有逗号拼接的多个邮箱。
- **2NF：** 两个候选键均为单属性，不存在部分函数依赖。
- **3NF：** 非主属性由候选键决定；本表不保存 `department_name`，因此不存在表内 `student_id → department_id → department_name` 这条非主属性传递链。已规定的非平凡依赖决定项都是超键，满足 3NF，在该依赖集合下也满足 BCNF。

院系信息能通过连接获取，是跨表引用，不是本表中已有的非主属性决定非主属性。增删学生不要求复制或删除院系目录。

### 3.3 教师 teachers

```text
teacher_id → teacher_no, teacher_name, department_id
teacher_no → teacher_id
```

`teacher_id` 和 `teacher_no` 各自闭包覆盖全表，且均最小；候选键为这两个单属性集合。教师姓名不唯一，院系 ID 也不能唯一定位一名教师。

- **1NF：** 每行一个教师，属性均为单值。
- **2NF：** 候选键均为单属性，不可能存在针对其真子集的部分依赖。
- **3NF：** 不把院系代码或名称存于本表，非主属性之间没有已规定的决定关系；所有已识别非平凡依赖左部均为超键。因此满足 3NF，在该依赖集合下也满足 BCNF。

教师尚未承担教学班时仍可独立登记，解决把教师资料混放在授课明细中造成的插入异常。

### 3.4 课程 courses

```text
course_id → course_code, course_name, credits, department_id
course_code → course_id
```

候选键为 `{course_id}` 和 `{course_code}`。课程名可能相同；学分或院系也不能决定课程。业务语义没有规定“某院系所有课程学分相同”等依赖。

- **1NF：** 每行一门课程，学分为单个数值，不在课程行保存教师列表或教学班列表。
- **2NF：** 两个候选键均为单属性，无部分依赖。
- **3NF：** 非主属性只由候选键决定，不保存院系名称、教师姓名或班级容量，没有已识别的非主属性传递依赖。满足 3NF，在该依赖集合下也满足 BCNF。

课程可以先进入目录再开班，最后一个教学班被删除也不导致课程目录丢失。

### 3.5 教学班 teaching_classes

```text
class_id → class_code, course_id, teacher_id, semester, capacity, enrolled_count
class_code → class_id
```

`class_id` 与 `class_code` 分别能决定全部属性，均为候选键。课程、教师与学期的组合没有唯一约束，也没有“一个组合最多开一班”的业务规定，因此不能把 `(course_id, teacher_id, semester)` 当作候选键。

- **1NF：** 每行一个教学班；只有一门课程、一位教师和一个学期，人数是单个整数。
- **2NF：** 候选键均为单属性，无部分依赖。
- **3NF：** 本表没有课程名称、学分、教师姓名等由外键决定的描述字段。`capacity` 不决定 `enrolled_count`：相同容量的不同班可有不同人数；反过来也不成立。现有函数依赖左部均为超键，满足 3NF，在该依赖集合下也满足 BCNF。

人数为派生缓存并不自动构成“非键决定非键”。`enrolled_count = 对 enrollments 的按班计数` 是跨表聚合约束，不是本表中 `capacity → enrolled_count` 或 `course_id → enrolled_count`。因此，**本表可以满足 3NF，同时仍存在需要主动维护的跨表冗余**。

数据库触发器在选退课时原子维护缓存；`trg_verify_enrollment_count` 为可延迟、初始延迟的约束触发器，在提交时强制比对明细与缓存，拒绝不一致事务。聚合审计提供额外复核；范式结论不能替代这些机制。

### 3.6 选课 enrollments

```text
(student_id, class_id) → enrolled_at, grade
```

闭包 `{student_id, class_id}⁺` 覆盖全表。单独 `student_id` 对应多个班，单独 `class_id` 对应多个学生，二者都不能决定选课时间或成绩，因此联合键最小，且为当前语义下唯一候选键。主属性为两个 ID。

- **1NF：** 每行只对应一个学生与一个教学班，时间和成绩均为单值；未录成绩用 `NULL`，不把多次成绩放成列表。
- **2NF：** 选课时间与成绩依赖联合键整体。同一学生不同班可以在不同时间选课并取得不同成绩，同一班不同学生亦然；不存在对任一主键分量的部分依赖。
- **3NF：** 非主属性仅有选课时间和成绩，没有“选课时间决定成绩”或“成绩决定选课时间”的业务规则，也没有其他非主属性中介。所有已识别非平凡依赖的决定项均为联合键的超集，满足 3NF，在该依赖集合下也满足 BCNF。

禁止更改两个身份字段是业务更新规则，不是新的函数依赖；修改成绩仍然允许。退课删除记录，再选课重新生成记录。

## 4. 从未规范化选课总表逐步拆分

### 4.1 未规范化记录与异常

考虑把所有资料堆在一张“学生选课总表”中：

```text
U0(
  学生ID, 学号, 学生姓名, 邮箱, 入学年份,
  学生院系ID, 学生院系代码, 学生院系名称,
  选课列表 = [
    教学班ID, 教学班代码, 学期, 容量, 人数,
    课程ID, 课程代码, 课程名, 学分,
    课程院系ID, 课程院系代码, 课程院系名称,
    教师ID, 工号, 教师姓名,
    教师院系ID, 教师院系代码, 教师院系名称,
    选课时间, 成绩
  ]
)
```

`选课列表` 是重复组，U0 不满足 1NF。若用字符串拼接列表，仍然不能把它当作符合业务原子性的选课属性。

将重复组展开成每个学生与教学班一行，得到原子化总关系 U1。暂用语义别名区分三个院系角色，学生、教师、课程的院系可以不同，不强行合并为一个“院系 ID”列。

U1 的一个候选键为 `(student_id, class_id)`；备用业务键组合可以通过学号和教学班代码导出。它存在以下问题：

| 异常 | 具体情形 |
|---|---|
| 插入异常 | 新课程尚无选课时，无法在以学生选课为一行的总表中自然登记 |
| 更新异常 | 修改一门课的学分或一位教师的姓名，需要修改所有相关选课行 |
| 删除异常 | 删除最后一条相关选课，可能同时丢失教学班、课程、教师的描述信息 |
| 重复存储 | 同一院系名称在学生、教师、课程及大量选课行中反复出现 |

### 4.2 从 1NF 到 2NF

在 U1 中：

```text
student_id → 学生基本资料及学生院系描述
class_id → 教学班基本资料、课程描述、教师描述及对应院系描述
(student_id, class_id) → enrolled_at, grade
```

学生描述和教学班描述分别依赖联合键的真子集，违反 2NF。拆成：

```text
S+(student_id, student_no, student_name, email, admission_year,
   student_department_id, student_department_code, student_department_name)

C+(class_id, class_code, semester, capacity, enrolled_count,
   course_id, course_code, course_name, credits,
   course_department_id, course_department_code, course_department_name,
   teacher_id, teacher_no, teacher_name,
   teacher_department_id, teacher_department_code, teacher_department_name)

E(student_id, class_id, enrolled_at, grade)
```

学生和教学班描述从选课表中移出，E 的非主属性完全依赖联合主键。S+ 与 C+ 使用单属性候选键，不再有该类部分依赖，但仍含传递依赖。

### 4.3 从 2NF 到 3NF

S+ 中存在：

```text
student_id → student_department_id
student_department_id → student_department_code, student_department_name
```

C+ 中存在：

```text
class_id → course_id
course_id → course_code, course_name, credits, course_department_id

class_id → teacher_id
teacher_id → teacher_no, teacher_name, teacher_department_id

course_department_id → course_department_code, course_department_name
teacher_department_id → teacher_department_code, teacher_department_name
```

把院系、课程、教师的独立描述分别提出：S+ 变成 students 与部门目录的引用；C+ 变成 teaching_classes、courses、teachers 及部门目录的引用；E 直接成为 enrollments。三个院系角色引用同一套全局院系目录，不增加三张不同的院系表。

该过程保留人数缓存的明示冗余，但不保留课程名、教师名等可以通过连接取得的描述字段。最终六表如第 1 节。

## 5. 二元分解的无损连接性

### 5.1 判据

在给定函数依赖集合 F 下，R 分解成 R1、R2，若：

```text
(R1 ∩ R2) → R1
或
(R1 ∩ R2) → R2
```

属于 F 的闭包，则该二元分解为无损连接分解。下面把多表拆分写成逐次二元分解，每步均用公共属性决定被提出的那一侧。

### 5.2 逐步验证

“剩余关系”保留公共连接键，但移除已提出的非键描述属性。

| 步骤 | 二元分解 | 公共属性 | 满足的决定关系 |
|---|---|---|---|
| 1 | U1 → S+ 与剩余 W1 | `student_id` | `student_id → S+` |
| 2 | W1 → C+ 与 E | `class_id` | `class_id → C+` |
| 3 | S+ → 学生院系角色目录 D_s 与 students | `student_department_id` | `student_department_id → D_s` |
| 4 | C+ → 带院系描述的课程 C_course+ 与剩余 W2 | `course_id` | `course_id → C_course+` |
| 5 | W2 → 带院系描述的教师 C_teacher+ 与 teaching_classes | `teacher_id` | `teacher_id → C_teacher+` |
| 6 | C_course+ → 课程院系角色目录 D_c 与 courses | `course_department_id` | `course_department_id → D_c` |
| 7 | C_teacher+ → 教师院系角色目录 D_t 与 teachers | `teacher_department_id` | `teacher_department_id → D_t` |

每步公共属性都是被提出关系的候选键，因此每步符合判据；逐步替换仍能无损重建原 U1 的选课事实。

这里三个 D 关系是同一院系目录在不同角色下的重命名。合并为 `departments` 的依据是“所有院系 ID、代码、名称属于统一院系目录”的已定语义和唯一约束，不是因为任意三张外形相同的表都可以合并。连接时要分别使用学生院系、课程院系、教师院系三个别名，不能强制它们的 ID 相等。

### 5.3 适用范围

上述无损性讨论针对满足 F 的原子化 U1 及其投影；不能用“可以连接”替代判据。最终数据库还允许没有选课的学生、没有开班的课程等独立记录，这些是总表本来难以表达的新合法状态。重建选课事实可以从 enrollments 出发做内连接；需要显示无选课学生或未开课课程时必须使用相应的外连接。

不把可空邮箱或成绩作为连接条件，避免用 SQL 空值语义冒充经典关系理论证明。

## 6. 依赖保持的范围

| 原业务依赖或约束 | 分解后的保持方式 |
|---|---|
| ID 决定本实体描述 | 各自保留于实体关系内，由主键保证一行的唯一对应 |
| 院系代码/名称、学号、工号、课程代码、教学班代码决定该实体 | 非空唯一约束保留备用候选键；本表可独立检查 |
| `(student_id, class_id) → enrolled_at, grade` | 完整保留于 enrollments，由联合主键实现 |
| 院系名称等传递得到的总表描述 | 由局部函数依赖的并集通过传递规则恢复，不必重复存储描述列 |
| 子表引用对象存在 | 外键保持；这属于包含依赖，不是普通函数依赖 |
| 人数不超过容量 | 单行 `CHECK` 及原子容量更新；不是普通函数依赖 |
| 人数等于选课明细条数 | 跨表聚合约束，由选退课触发器维护，延迟约束触发器在提交时强制核对，审计额外复核；不能声称通过 3NF 分解或局部唯一键自动保持 |
| 选课身份不允许更新 | 更新检查触发器；属于状态转换规则，不是普通函数依赖 |

因此，本设计保持第 3 节明确列出的局部业务函数依赖，并能用其并集推出总表的描述性传递依赖。这个结论不扩展到所有现实学校政策，也不涵盖“跨表计数正确”这种非普通 FD 约束。

## 7. 结论与实际核验要求

在本文明确给定的函数依赖集合下，六个关系均满足 1NF、2NF 和 3NF；其非平凡函数依赖决定项均为超键，因此也满足该集合下的 BCNF 判据。该判断依据候选键、闭包和业务语义，而不是“有代理主键就自动规范化”。

实际 DDL 已对照检查备用键、可空性、七条外键和更新检查；29 项自动化测试已覆盖人数原子维护、提交时校验和并发争抢最后名额，结果见 `docs/05_测试报告.md`。本文仍是推导说明，不充当学生独立分析已经完成的证明；函数依赖和范式结论须由学生用自己的语言复核。
