# 高校教学管理系统物理设计

## 1. 平台与实现边界

目标环境为 PostgreSQL 16、Java 17、pgJDBC、JDBC 命令行应用。数据使用数据库常规表存储，标识列采用 `bigint GENERATED ALWAYS AS IDENTITY`，选课时间采用 `timestamptz`，学分和成绩使用精确数值类型 `numeric`。

已确认的本地环境是 PostgreSQL 服务端 16.16、客户端 16.15，使用来自 Maven 中央仓库的 Zonky Windows 二进制启动独立本地实例，监听 `127.0.0.1:55432`，未全局安装 PostgreSQL。服务端与客户端的小版本分别记录，不混称为同一版本；项目仍以 Java 17 为目标兼容版本，具体运行 JDK 的实测信息以运行记录为准。

本项目数据规模用于课程演示，先使用默认表空间和普通 B-tree 索引，不引入分区、读写分离、连接池或额外 ORM。性能是否满足更大规模，需要在真实数据量和查询计划下另行测量。

本文对照 `sql/create_tables.sql`、`sql/insert_data.sql`、`sql/query.sql` 及 JDBC 源码说明物理实现。建库、初始化、八类查询和 29 项自动化测试已于 2026-11-18 在本地 PostgreSQL 16.16 实际执行；性能基准和高并发压力测试未做，不能把功能验证扩大为生产容量结论。

## 2. 表、字段与完整性约束

### 2.1 全局约定

1. 五张实体表的主键均为 `bigint` identity；`enrollments` 不增加无业务必要的代理 ID。
2. 所有字段除邮箱、成绩外均为 `NOT NULL`。主键本身保证非空，其他必填列仍应明确声明。
3. 每个字符串列均限制长度并检查 `btrim(列) <> ''`。该检查不自动规范存储值，也不承诺拒绝所有 Unicode 空白字符。
4. 七条外键均显式采用 `ON DELETE RESTRICT`，不使用级联删除；实际 SQL 未声明 `ON UPDATE`，采用默认 `NO ACTION`，不能声称已显式设置 `ON UPDATE RESTRICT`。
5. 主键和唯一约束由数据库建立对应唯一索引，不再手工建立同列重复索引。

### 2.2 分表配置

| 表 | 字段定义与主要约束 |
|---|---|
| `departments` | `department_id bigint identity PRIMARY KEY`；`department_code varchar(12) UNIQUE NOT NULL`；`department_name varchar(80) UNIQUE NOT NULL` |
| `students` | `student_id bigint identity PRIMARY KEY`；`student_no varchar(20) UNIQUE NOT NULL`；`student_name varchar(60) NOT NULL`；`department_id bigint NOT NULL` 外键；`email varchar(120) UNIQUE` 可空；`admission_year smallint NOT NULL CHECK (admission_year BETWEEN 2000 AND 2100)` |
| `teachers` | `teacher_id bigint identity PRIMARY KEY`；`teacher_no varchar(20) UNIQUE NOT NULL`；`teacher_name varchar(60) NOT NULL`；`department_id bigint NOT NULL` 外键 |
| `courses` | `course_id bigint identity PRIMARY KEY`；`course_code varchar(20) UNIQUE NOT NULL`；`course_name varchar(100) NOT NULL`；`credits numeric(3,1) NOT NULL CHECK (credits > 0 AND credits <= 10)`；`department_id bigint NOT NULL` 外键 |
| `teaching_classes` | `class_id bigint identity PRIMARY KEY`；`class_code varchar(24) UNIQUE NOT NULL`；`course_id bigint NOT NULL` 外键；`teacher_id bigint NOT NULL` 外键；`semester varchar(11) NOT NULL`；`capacity integer NOT NULL CHECK (capacity BETWEEN 1 AND 500)`；`enrolled_count integer NOT NULL DEFAULT 0 CHECK (enrolled_count BETWEEN 0 AND capacity)` |
| `enrollments` | `student_id bigint NOT NULL` 外键；`class_id bigint NOT NULL` 外键；`enrolled_at timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP`；`grade numeric(5,2) CHECK (grade BETWEEN 0 AND 100)` 可空；`PRIMARY KEY (student_id, class_id)` |

字符串非空检查还需逐列落地，不能只依靠上表的 `NOT NULL`。可空邮箱的检查应为：

```sql
CHECK (email IS NULL OR btrim(email) <> '')
```

当前唯一性按实际数据库比较语义处理，不额外声称邮箱或业务代码忽略大小写。多个学生可以没有邮箱；空串不是“没有邮箱”，应在输入端转换为 `NULL` 或由数据库拒绝。

### 2.3 学期校验

学期例如 `2026-2027-1`、`2026-2027-2`。`2026-2028-1`、`2026-2027-3`、省略位数或附带空格的字符串均不合法。建议使用带分支的检查，先确认格式，再做数值转换：

```sql
CHECK (
    CASE
        WHEN semester ~ '^[0-9]{4}-[0-9]{4}-[12]$'
        THEN substring(semester FROM 6 FOR 4)::integer
             = substring(semester FROM 1 FOR 4)::integer + 1
        ELSE false
    END
)
```

这样不依赖多个布尔子表达式的求值先后，格式错误时不会先转换非法数字。本项目没有额外规定学期年份必须与当前年份接近，不擅自增加该限制。

### 2.4 数值、时间与空值

学分为 `numeric(3,1)`，成绩为 `numeric(5,2)`，不得替换成浮点数后再比较边界。数据库会把输入转换为字段的小数位数，范围检查约束存储值；若需要拒绝超出精度的原始输入，CLI 应单独检查并测试。

`CURRENT_TIMESTAMP` 表示当前事务时间，不保证每条语句都有不同时间。`timestamptz` 表示时间点，显示受会话时区影响；验收时需统一时区口径，不把显示时区变化误判为时间点被修改。

`AVG(grade)` 忽略未录入的空成绩。`COUNT(grade)` 表示已录成绩数，`COUNT(*)` 表示查询行数；对左连接的教学班人数应使用 `COUNT(e.student_id)`，避免把无选课班的外连接占位行误算为 1。

## 3. 触发器、并发与事务设计

### 3.1 人数缓存不变量

对每个教学班应始终成立：

```text
0 ≤ enrolled_count ≤ capacity
enrolled_count = COUNT(enrollments WHERE class_id = 当前班ID)
```

第一行可由单行 `CHECK` 检查；第二行依赖选课明细，是跨表聚合约束，不能写成引用其他表的普通 `CHECK` 并据此声称数据库自动保证一致。

### 3.2 选课触发器

一次选课插入所触发的人数维护，必须采用下面形式的原子更新。以下是使用 `NEW` 的触发器函数片段设计，不是可直接独立执行的普通 SQL：

```sql
UPDATE teaching_classes
SET enrolled_count = enrolled_count + 1
WHERE class_id = NEW.class_id
  AND enrolled_count < capacity;
```

`maintain_enrollment_count()` 检查实际影响行数：目标教学班不存在时使用 SQLSTATE `23503`，满额时使用 `23514`。人数维护与选课插入属于同一语句/事务，重复主键、外键失败或随后发生的回滚都必须撤销人数变化。

实际 `trg_enrollment_count` 是选课表上的行级 `BEFORE INSERT OR DELETE OR UPDATE` 触发器，在插入前完成名额占用。仍必须由真实回滚和并发测试验证行为，不能以 Java 中“查询剩余人数再插入”作为唯一保护。

在通常的 `READ COMMITTED` 演示下，更新同一教学班行的并发事务会竞争行锁，等待后仍需满足容量条件才可成功更新。`EnrollmentService.enroll` 将多个教学班 ID 复制并升序排序，然后在一个显式事务内逐条执行，避免不同批次按反向教学班次序获取锁；任一失败整体回滚。统一锁序减少这一路径的死锁风险，不等于所有其他写入路径都不可能死锁；不能把序列化失败、死锁等所有异常都显示为“已满”。

### 3.3 退课及身份更新限制

退课按联合键删除选课，删除触发器在同一事务内对相应班执行人数减一。负数由教学班行的 `CHECK` 拒绝，跨表差异由提交时的一致性校验检查。不存在的选课删除零行，不触发一次实际退课，不应减人数。

同一触发器的更新分支比较 `NEW`、`OLD` 中两个非空身份字段，拒绝把已有选课的 `student_id` 或 `class_id` 改成其他值。只更新成绩不改变人数。换班若需作为一个整体执行，应使用同一 JDBC 事务“删除旧选课、插入新选课”；若新班已满，整个事务回滚，原选课和原人数恢复。当前不把独立换班入口写成已实现功能。

### 3.4 提交时强制一致性校验与写入边界

人数缓存只能通过规定的选退课维护路径改变。CLI 和 DAO 不应提供直接修改 `enrolled_count` 的入口；初始化教学班应使用默认 0，再通过正常插入选课触发计数，不先填人数又再次触发累加。调整容量仍需满足 `capacity >= enrolled_count`。

实际 SQL 还建立 `trg_verify_enrollment_count`：

```sql
CREATE CONSTRAINT TRIGGER trg_verify_enrollment_count
AFTER INSERT OR UPDATE ON teaching_classes
DEFERRABLE INITIALLY DEFERRED
FOR EACH ROW EXECUTE FUNCTION verify_enrollment_count();
```

该触发器默认延迟到 `COMMIT` 时读取目标班当前缓存及选课真实 `COUNT(*)`。只要不相等，就以 SQLSTATE `23514` 拒绝提交。它读取最终状态而非直接拿触发时旧快照的 `NEW.enrolled_count` 比较，因而允许同一事务完成多次合法选退课后再作整体校验。

因此，在触发器正常启用的普通事务中，直接把人数改成范围内却与明细不一致的值，也无法提交；校验不只是权限建议或事后审计。由于检查可延迟，事务中间语句成功不代表最终提交成功，JDBC 必须捕获 `commit()` 报错并回滚。对选课时间或成绩的普通更新不影响计数；选退课则通过人数更新触发这一提交检查。

当前可信操作员原型仍不等于安全权限系统，本项目不声称已部署数据库角色分权或登录认证。有权禁用触发器、修改函数、执行未受上述行级触发器覆盖的维护操作的高权限用户，仍应受独立运维约束。不能把正常事务的一致性保护描述成防止管理员绕过的安全隔离。

若正式用于多人操作，应在独立验证后实施最小权限：应用账号不作为表所有者，不直接拥有人数列的更新权限，只授予必要列和受控业务入口的权限。触发器若需要以受控所有者权限维护人数，还须同步设计函数所有权、固定安全搜索路径、调用权限和对象创建权限，不能仅写一个列权限撤销语句就宣称方案可用。

聚合审计用于额外复核，不替代提交时校验或原子容量控制。若审计发现异常，应先停止相关业务并查明维护操作或绕过路径，再在受控维护事务中重算。

### 3.5 JDBC 事务边界

| 操作 | 必须执行的数据库动作 | 提交与失败处理 |
|---|---|---|
| 批量选课 | 教学班 ID 升序；逐条插入选课并原子占位 | 显式事务，全部成功且延迟校验通过后提交；任一异常整体回滚 |
| 退课 | 自动提交模式下按联合键执行单条删除，触发人数减一 | 单语句事务；包括提交时校验在内的失败撤销该次操作；零行明确提示 |
| 成绩录入 | 自动提交模式下按联合键执行单条 `UPDATE grade` | 单语句事务；非法成绩撤销；检查记录存在；不改变人数 |
| 学生修改/删除 | 参数化更新或删除 | 检查影响行数；外键拒绝删除时明确说明关联关系 |

连接通过 `try-with-resources` 关闭；批量选课关闭自动提交，并在异常路径显式 `rollback`，不只打印异常后继续提交。当前单次退课和录分利用数据库单语句事务原子性，不把它们描述成各自已有显式 `setAutoCommit(false)` 代码。复用连接时应恢复状态。错误提示应区分唯一性、外键、检查约束及并发异常，并保留可诊断信息而不泄露连接密码。

## 4. 索引设计

### 4.1 已有索引与禁止重复建设的部分

主键和各 `UNIQUE` 约束已提供索引，包括 `students(student_no)`、`teaching_classes(class_code)` 等业务编号，以及选课联合主键 `(student_id, class_id)`。

学生按 `student_id` 查询自己的全部选课，已能使用联合主键的最左前缀，不再单独建立 `enrollments(student_id)`。反过来按 `class_id` 查名单不能据此认为有同样的前缀支持，需要单独评估班级索引。

### 4.2 已定义的非重复辅助索引

以下七个辅助索引已在 `sql/create_tables.sql` 中定义。

| 索引列 | 主要用途 | 与现有索引的关系 |
|---|---|---|
| `students(department_id)` | 按院系统计或查询学生，检查院系删除时的引用 | 不是学生主键或学号索引前缀 |
| `teachers(department_id)` | 查询院系教师及外键引用 | 不与教师主键、工号唯一索引重复 |
| `courses(department_id)` | 查询院系课程及外键引用 | 不与课程主键、课程代码唯一索引重复 |
| `teaching_classes(course_id)` | 按课程查开班及课程外键引用检查 | 不与教学班主键、教学班代码唯一索引重复 |
| `teaching_classes(teacher_id)` | 查询教师授课及教师引用检查 | 不由课程复合索引覆盖 |
| `teaching_classes(semester)` | 按学期全局查教学班和汇总 | 与课程索引服务不同筛选入口 |
| `enrollments(class_id)` | 班级名单、成绩统计、退课计数核对及外键查找 | `class_id` 不是现有联合主键的最左前缀 |

PostgreSQL 不因声明外键就自动为所有子表外键列建立索引，因此要按查询和引用检查需要选择这些索引。若后续实测需要将单列课程索引替换为 `(course_id, semester)`，应复核重复前缀，不再同时保留无必要的单列版本。小规模样本可能仍采用顺序扫描，这是成本选择，不代表索引创建失败。当前不为姓名、成绩、所有可筛选列一律建索引，也不声明未经实测的性能提升比例。

## 5. 初始化数据与一致性审计

### 5.1 数据规模及顺序

六表必须各自不少于 10 条；“总计 60 条”不能替代每表下限。当前已成功建库和初始化，基线数量为：

| 院系 | 学生 | 教师 | 课程 | 教学班 | 选课 |
|---|---|---|---|---|---|
| 10 | 20 | 10 | 10 | 12 | 24 |

`sql/insert_data.sql` 按以下顺序初始化：

```text
departments
→ students、teachers、courses
→ teaching_classes（人数默认 0）
→ enrollments（通过触发器形成实际人数）
```

初始化资料为课程演示用虚构数据。当前脚本中 20 名学生均有选课、10 门课程均有开班、12 个教学班均有人选，邮箱均非空；这些事实不妨碍用 `LEFT JOIN` 演示语法，但初始结果本身不能证明空匹配分支已被测试。当前脚本提供未录成绩和满额班，零分、满分、空邮箱、未选课学生、未开班课程、空班等边界场景应在专用测试事务或数据中构造，不能声称种子数据已经全部覆盖。

同一学生可选择同课程不同教学班，也可跨学期重修。不要在种子数据或测试中错误地把这两种情况判为违反当前规则。

### 5.2 人数缓存审计 SQL

下列查询应返回零行；返回非零行表示存在差异。当前已有 `sql/verify.sql` 包含逐表行数下限和该类一致性检查，应在最终建库、初始化及并发测试后实际运行并保留结果。

```sql
SELECT tc.class_id,
       tc.class_code,
       tc.enrolled_count AS cached_count,
       COALESCE(e.actual_count, 0) AS actual_count
FROM teaching_classes tc
LEFT JOIN (
    SELECT class_id, COUNT(*) AS actual_count
    FROM enrollments
    GROUP BY class_id
) e ON e.class_id = tc.class_id
WHERE tc.enrolled_count <> COALESCE(e.actual_count, 0)
ORDER BY tc.class_id;
```

审计时应使用能反映已提交状态的一致读取口径，不比较两个互不对应时刻的独立统计结果。运行审计不会自动修复数据。

## 6. 八条查询设计

本节与当前 `sql/query.sql` 的 Q1—Q8 对应，覆盖单表 2、多表关联 2、分组及 `HAVING` 1、嵌套 2、复杂业务 1。固定学号 `S2026001` 和课程代码 `C001` 来自初始化数据，JDBC 对外部输入使用参数化查询。

### Q1：单表条件查询一——按入学年份查询学生

```sql
SELECT student_no, student_name, admission_year
FROM students
WHERE admission_year = 2026
ORDER BY student_no;
```

### Q2：单表条件查询二——查询至少三学分的课程

```sql
SELECT course_code, course_name, credits
FROM courses
WHERE credits >= 3
ORDER BY credits DESC, course_code;
```

### Q3：多表关联查询一——学生选课成绩明细

```sql
SELECT s.student_no,
       s.student_name,
       tc.class_code,
       c.course_name,
       t.teacher_name,
       e.grade
FROM enrollments e
INNER JOIN students s ON s.student_id = e.student_id
INNER JOIN teaching_classes tc ON tc.class_id = e.class_id
INNER JOIN courses c ON c.course_id = tc.course_id
INNER JOIN teachers t ON t.teacher_id = tc.teacher_id
WHERE s.student_no = 'S2026001'
ORDER BY tc.class_code;
```

对应第一种 JDBC 报告的按学号查询语义。该查询连接五张表，满足三表以上查询要求；没有选课的学生不会出现在内连接结果中。

### Q4：多表关联查询二——保留未选课学生的选课数量

```sql
SELECT s.student_no,
       s.student_name,
       COUNT(e.class_id) AS class_count
FROM students s
LEFT JOIN enrollments e ON e.student_id = s.student_id
GROUP BY s.student_id
ORDER BY s.student_no;
```

使用选课侧非空键计数，无选课学生应显示 0，不用 `COUNT(*)` 把左连接占位行计为一次选课。PostgreSQL 可利用分组主键对同表其他字段的函数依赖，允许在此选择学号和姓名。

### Q5：分组统计查询——筛选选课人次不少于三次的课程

```sql
SELECT c.course_code,
       c.course_name,
       COUNT(e.student_id) AS enrollment_count,
       ROUND(AVG(e.grade), 2) AS average_grade
FROM courses c
INNER JOIN teaching_classes tc ON tc.course_id = c.course_id
INNER JOIN enrollments e ON e.class_id = tc.class_id
GROUP BY c.course_id
HAVING COUNT(e.student_id) >= 3
ORDER BY c.course_code;
```

这里统计选课人次，不是去重学生数；不同班级的同一学生可以计多次。当前第二种 JDBC 报告是另一条教学班级查询，包含课程、教师、容量、缓存人数和平均分，不把本条 SQL 的课程分组结果误写成该报告的实际输出。

### Q6：嵌套查询一——使用 IN 查询选择 C001 课程的学生

```sql
SELECT s.student_no, s.student_name
FROM students s
WHERE s.student_id IN (
    SELECT e.student_id
    FROM enrollments e
    INNER JOIN teaching_classes tc ON tc.class_id = e.class_id
    WHERE tc.course_id = (
        SELECT course_id FROM courses WHERE course_code = 'C001'
    )
)
ORDER BY s.student_no;
```

### Q7：嵌套查询二——使用 EXISTS 查询有待录成绩的教师

```sql
SELECT t.teacher_no, t.teacher_name
FROM teachers t
WHERE EXISTS (
    SELECT 1
    FROM teaching_classes tc
    INNER JOIN enrollments e ON e.class_id = tc.class_id
    WHERE tc.teacher_id = t.teacher_id
      AND e.grade IS NULL
)
ORDER BY t.teacher_no;
```

### Q8：复杂业务查询——各院系课程、开班、选课与成绩汇总

```sql
SELECT d.department_code,
       d.department_name,
       COUNT(DISTINCT c.course_id) AS course_count,
       COUNT(DISTINCT tc.class_id) AS class_count,
       COUNT(e.student_id) AS enrollment_count,
       ROUND(AVG(e.grade), 2) AS average_grade,
       ROUND(
           100.0 * COUNT(*) FILTER (WHERE e.grade >= 60)
           / NULLIF(COUNT(e.grade), 0),
           2
       ) AS pass_rate_percent
FROM departments d
LEFT JOIN courses c ON c.department_id = d.department_id
LEFT JOIN teaching_classes tc ON tc.course_id = c.course_id
LEFT JOIN enrollments e ON e.class_id = tc.class_id
GROUP BY d.department_id
ORDER BY d.department_code;
```

用 `DISTINCT` 避免一对多连接把课程数和班级数重复计算。平均分直接基于每条非空成绩计算，不平均各班的平均分；及格率分母为已录成绩数，`NULLIF` 避免除零。没有已录成绩时平均分、及格率均为 `NULL`，不把未录分当成零分。

院系口径取课程所属院系，而非学生或教师所属院系。本查询不统计容量；若后续增加容量汇总，必须先按班聚合或另行去重，不能在展开后的选课明细上直接累加容量。

`enrollment_count` 是选课人次；一个学生选同课程两个班会计两次，不把该指标误称为去重学生数。
